# 批次原型兼容与降级

## 隔离而非旧记录迁移

新batch/v1命令仅在显式data-root的batches目录保存冻结manifest、增量ledger、queue和lineage。现有register/prepare/ingest/review及人工审核状态不由批次接口调用或转换。不会自动扫描records，不将completed当作语义覆盖，不生成旧record候选。该原型仍为实验性能力，使用本地build入口；npx仍获取已发布版本。

## 现有协议限制

- 输入schema严格拒绝未知字段；不将旧单记录packet作为批次输入。
- 时间模式仅created及显式来源；跨月活动模式未实现，不能悄悄扩大日期范围。
- 来源增长用新batch id的append，不改旧快照，不重读已冻结父来源，不继承语义判断。
- exact正文阅读引用与语义标签复用分开；reused_exact提交禁用，直到身份和上下文验证协议落实。
- batch-submission/v1单分类不能同时表达纠错和介入；新增v2以显式labels表达并存，新实现可读取旧账本，旧客户端不保证可读含v2的新账本。v2现可附unverified返工证据和待审candidates；不认证因果、不授予审批。只实现早期labels版本的旧v2客户端也可能因strict未知字段拒绝新账本，必须核对字段能力，不仅比较schema名字。不能移除rework/candidates重算哈希以强行兼容，不能降级丢掉一个标签后声称完整。
- 新可选queue模板、游标和claim请求历史对旧queue保持读取兼容；存在的引用须合法。合成回归已验证移除所有新可选字段后查询不改写旧queue；旧状态目标不存在时仍拒绝。损坏不自动修复。
- 1 MiB完整submission上限可能拒绝旧本地试验的大载荷；先核对账本已有request，再按实际审阅目标分开新请求，不截断证据或重新执行旧成功请求。

## 停用与回退

当质量对照失败或协议未满足语义需求，停止新worker分配，按当前租约分类取消；保留冻结证据和账本用于人工审计。继续使用既有单记录语义流程时，须用户明确选择来源和运行范围，不从batch自动重放全部旧记录。旧候选的审批/撤销/修改始终走现有人工审核流程。

不删除batches以假装恢复、不覆盖manifest、不篡改expected_version、不强制解锁、不撤销旧人工决定。需要删除含敏感内容的试验数据时另行获得明确目标路径授权；当前无自动保留期或删除功能。

## 放行仍未满足

工程合成回归不能替代P0真实基线、身份核验、完整双标签返工协议、宿主执行适配、人工金标全覆盖及同模型质量/效率对照。P5真实九月应用必须P4放行后执行，候选仍待人工审核；不授权npm发布。当前遗留工程项见[协议能力边界](<BATCH_PROTOCOL.md>)，中断恢复见[恢复手册](<BATCH_RECOVERY.md>)。
